단순 챗봇(LLM)과 AI 에이전트(Agent)는 무엇이 다를까요?

일반 AI 챗봇이 질문에 대답만 하는 '똑똑한 백과사전'이라면, AI 에이전트는 목표를 달성하기 위해 스스로 계획을 세우고, 사내 규칙(지침)을 지키며, 도구(스킬·플러그인·MCP·API)를 직접 실행하는 '자율 실무 담당자'입니다.

에이전트 개발 입문자 필수 용어 7가지 정리

용어들이 헷갈릴 때는 '회사 조직'이나 '스마트폰·자동차'에 비유하면 명확하게 구분됩니다.

1. 워크플로우 (Workflow) 업무 흐름도

특정 목표를 달성하기 위해 단계별로 정해진 작업 순서입니다. (예: 1단계 데이터 수집 → 2단계 불량 판정 → 3단계 보고서 생성)

💡 핵심 포인트: AI에게 모든 걸 맡기지 않고, 정해진 길(순서)을 따라가게 설계하면 결과가 훨씬 안정적입니다.
2. 하네스 (Harness) 안전장치 및 실행 틀

원래 말(Horse)을 제어하기 위해 씌우는 '마구(고삐·안장)'에서 유래했습니다. AI 모델이 폭주하거나 잘못된 파일을 지우지 못하도록 감싸는 실행 환경, 권한 통제, 반복 루프 제어 프레임워크입니다. (예: Codex CLI, ChatGPT 데스크톱 앱)

💡 핵심 포인트: 같은 AI 모델이라도 어떤 '하네스' 위에서 돌리느냐에 따라 코딩 실력과 안전성이 크게 달라집니다.
3. Agent 지침 (Instructions) 행동 수칙 & 규칙

에이전트가 작업할 때 항상 머릿속에 넣고 지켜야 할 역할, 출력 형식, 제약 조건입니다. 프로젝트 폴더의 AGENTS.md 파일이 대표적입니다.

💡 핵심 포인트: "원본 CSV는 절대 수정하지 마", "답변은 한국어로 작성해" 같은 규칙을 적어두는 곳입니다.
4. 스킬 (Skills) 전문 작업 레시피

에이전트가 특정 도메인 작업을 정확하게 수행할 수 있도록 지침(SKILL.md) + 스크립트 + 검증 기준을 하나로 묶어둔 모듈입니다.

💡 핵심 포인트: '일일 운영 브리핑 스킬', '선박 자재 지연율 계산 스킬'처럼 반복 업무 매뉴얼을 저장해 두고 짧은 명령으로 호출합니다.
5. 플러그인 (Plugins) 확장 기능 앱

기본 에이전트 플랫폼이나 편집기(VS Code, ChatGPT 앱 등)에 추가 기능을 손쉽게 끼워 넣는 완제품 확장 프로그램입니다. 스마트폰에 앱을 설치하는 것과 같습니다.

💡 핵심 포인트: 웹 검색 플러그인, VS Code 확장 프로그램, 외부 서비스 커넥터 등을 켜면 AI의 손발 기능이 즉시 늘어납니다.
6. MCP (Model Context Protocol) 만능 표준 연결 규격

AI와 외부 데이터(로컬 폴더, 데이터베이스, GitHub, 슬랙 등)를 연결할 때 제각각 코드를 짜지 않고 하나의 표준 규약으로 연결하는 개방형 프로토콜입니다.

💡 핵심 포인트: 예전엔 기기마다 충전기가 달랐지만 이제 USB-C 하나로 통일된 것처럼, AI 도구 연결의 표준입니다.
7. API 활용 (Application Programming Interface) 외부 시스템 데이터 통신

사내 시스템, 공공데이터포털, 기상청, 사내 메신저 등 다른 소프트웨어의 기능이나 데이터를 코드로 호출해 가져오는 방법입니다. 에이전트가 실시간 환율이나 선박 입출항 정보를 조회할 때 API를 호출합니다.

💡 MCP와 API의 관계: API가 각 식당의 고유한 '주문 방식'이라면, MCP는 AI가 여러 식당의 API를 똑같은 방식으로 쉽게 주문할 수 있게 표준화해 준 '통합 표준 단자'에 가깝습니다.

헷갈리기 쉬운 3가지 한눈에 비교: 스킬 vs 플러그인 vs MCP

세 가지 모두 AI의 능력을 확장해 주지만, 무엇으로 만들어졌고 어떻게 장착하는지가 다릅니다.

구분 스킬 (Skills) 플러그인 (Plugins) MCP (표준 프로토콜)
핵심 정체 자연어 지침(SKILL.md) 기반의 업무 매뉴얼 코드로 개발된 완제품 확장 프로그램 외부 데이터·도구와 연결하는 개방형 표준 규격
제작 및 장착 현업 담당자가 마크다운 문서로 직접 작성·저장 스토어/마켓에서 클릭해 설치하거나 활성화 MCP 서버 주소를 설정 파일에 연결해 플러그처럼 사용
실습 예시 일일 운영 브리핑 생성 및 원본 보존 검증 스킬 VS Code Codex 확장, 웹 검색·코드 인터프리터 로컬 파일 시스템, GitHub, 사내 DB 표준 연결
일상 비유 신입사원에게 주는 '업무 인수인계서' 스마트폰에 새로 까는 '전용 앱(App)' 어떤 기기든 바로 꽂히는 'USB-C 표준 단자'

에이전트를 움직이는 3대 핵심 작동 원리 (실무 필수 보조 개념)

위 7가지 부품을 조립한 뒤, 에이전트가 실제로 작동할 때 내부에서 돌아가는 핵심 메커니즘입니다.

A. 도구 호출 (Tool Use)

AI가 말로만 대답하는 대신 "지금 daily_brief.py를 실행해 줘" 또는 "파일을 읽어 줘"라고 구조화된 실행 신호를 보내 도구를 작동시키는 핵심 능력입니다.

💡 연결 관계: 두뇌(LLM)가 Tool Use라는 손으로 스킬·플러그인·MCP·API를 집어 사용합니다.
B. 컨텍스트 & 메모리

현재 대화창에 유지되는 작업 기억(단기 기억: 컨텍스트)과, 파일·DB에 저장해 다음 세션에서도 꺼내 쓰는 기록(장기 기억: AGENTS.md, SKILL.md, latest.json)입니다.

💡 실무 팁: 대화가 길어지면 단기 기억이 꽉 차므로, 중요 규칙은 반드시 파일(장기 기억)로 저장해야 합니다.
C. 사람 승인 (Human-in-the-Loop)

에이전트가 파일을 수정하거나 터미널 명령을 실행하기 직전, 하네스의 권한 설정(/permissions)에 따라 사람에게 최종 실행 허락을 묻는 안전 절차입니다.

💡 사내 원칙: AI 결과물의 사실 검증과 최종 실행 승인 책임은 항상 현업 담당자 본인에게 있습니다.

꼭 알아야 할 설계 선택: 워크플로우 vs 에이전트

무조건 AI에게 모든 자율성을 주는 것이 정답은 아닙니다. 업무 성격에 따라 두 가지 방식을 조합해야 합니다.

1. 워크플로우 중심 (기차 레일 방식)

개발자가 미리 [A → B → C] 순서를 코드로 고정해 두고, 각 단계에서만 AI의 지능을 빌려 쓰는 방식입니다.

✅ 언제 사용할까요?

• 매일 아침 8시에 실행하는 일일 자재/품질 정형 보고서

• 계산 공식과 출력 양식이 엄격하게 정해진 업무

👍 장점: 결과물이 예측 가능하고 오류가 적으며 비용이 저렴함
2. 자율 에이전트 중심 (택시 운전 방식)

목적지(목표)만 알려주면 AI가 상황을 보며 스스로 도구를 고르고, 에러가 나면 고쳐가며 목표를 달성할 때까지 반복 실행하는 방식입니다.

✅ 언제 사용할까요?

• 코드에 버그가 났을 때 원인을 찾아 수정하는 디버깅

• 정해지지 않은 다양한 데이터를 탐색해 인사이트를 찾는 업무

👍 장점: 복잡한 예외 상황에 유연하게 대처하며 사람처럼 문제를 해결함

실전 시나리오: "선박 자재 납기 지연 브리핑 에이전트" 조립 예시

7가지 개념과 3대 작동 원리가 실제 우리 실습(1차시~5차시)에서 어떻게 하나로 합쳐지는지 확인해 보세요.

1. 하네스
Codex CLI & ChatGPT 데스크톱 앱: 터미널과 앱 환경에서 파이썬 코드를 실행하고 파일 수정 권한(/permissions)을 통제하는 안전 울타리 역할을 합니다.
2. Agent 지침
AGENTS.md & 사내 AI 활용 규칙: "원본 CSV는 절대 수정하지 마라", "당일 납기는 지연에서 제외하라", "보안 금지 정보는 입력하지 마라"는 기본 원칙을 부여합니다.
3. 스킬
kship-operations-brief (SKILL.md): 반복되는 운영 브리핑 실행 순서와 산출물 5종 검증 절차를 매뉴얼화하여 짧은 요청만으로 재사용할 수 있게 합니다.
4. 플러그인
VS Code 확장 & 앱 프로젝트 연동 커넥터: 코드 편집기 안에서 AI 에이전트가 터미널 실행, 코드 비교(Diff), 가상환경(.venv) 파이썬 구동을 직접 수행하도록 기능을 확장합니다.
5. MCP
로컬 파일 시스템 & GitHub 표준 연결: 에이전트가 내 PC의 data/material_orders.csv를 표준 규격으로 읽고 generated/ 폴더에 결과를 저장합니다.
6. API 활용
외부 시스템 연동 (확장): 추후 사내 ERP API나 환율 API, 사내 메신저 웹훅 API를 연결하면 실시간 자재 단가 환산 및 담당자 알림까지 자동화할 수 있습니다.
7. 워크플로우
daily_brief.py & GitHub Actions 파이프라인: [데이터 검증 → 지연 계산 → Markdown/HTML 보고서 생성 → 공급사 초안 작성]의 정해진 절차를 매일 동일하게 수행합니다.
이 과정에서 실시간으로 작동하는 3대 핵심 원리
① 도구 호출 (Tool Use)

AI가 직접 암산하지 않고 .\.venv\Scripts\python.exe daily_brief.py 명령을 호출해 정확한 파이썬 계산 결과를 받아옵니다.

② 컨텍스트 & 메모리

새 대화를 열어도 AGENTS.md, SKILL.md, latest.json에 저장된 장기 기억을 읽어 직전 기준일과 규칙을 이어갑니다.

③ 사람 승인 (Human-in-the-Loop)

파일 쓰기나 외부 전송 전 터미널 승인 창에서 담당자가 내용을 확인·허가하며, 생성된 초안도 담당자 검토 후 발송합니다.
