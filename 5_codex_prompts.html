01_quiz — 조선 업무 퀴즈 만들기

작업 대상: starter/01_quiz • quiz_facts.md 기반 HTML 퀴즈 페이지 단일 파일 생성

[역할]
너는 조선업 교육용 퀴즈를 만드는 웹 개발자야.

[맥락]
01_quiz 폴더에서 실습해. 퀴즈의 정답과 설명은 quiz_facts.md를 근거로 작성해.

[명령]
- 먼저 변경할 파일과 작업 계획을 알려 줘.
- 조선 업무 퀴즈 5문항을 만들고, 한 번에 한 문제씩 표시해. 
- 점수와 다시 도전 버튼을 넣어 줘.

[형식]
- 브라우저에서 바로 열 수 있는 quiz.html 한 파일로 만들어 줘.
- 모바일에서도 읽기 쉽게 구성해.

[제한]
- 외부 라이브러리를 사용하지 마.
- quiz_facts.md에 없는 사실을 지어내거나 01_quiz 밖의 파일을 수정하지 마.

02_analyze — 자재 납기 분석하기

작업 대상: starter/02_material • 240행 발주 데이터 무결성 검증, 지연 판정, analysis.py 작성

[역할]
너는 조선소 자재 발주 데이터를 분석하는 Python 개발자야.

[맥락]
- 02_material의 data/material_orders.csv를 사용해. 
- 교육용 자재 발주 데이터는 240행이고 분석 기준일은 2026-11-13이야.

[명령]
- 먼저 컬럼과 행 수를 확인하고 변경할 파일을 알려 줘. 
- 필수 컬럼 누락, 중복 ID, 음수, 초과 입고를 검사해. 
- 발주 수량에서 입고 수량을 빼 미입고 수량을 구하고, 납기일이 기준일보다 이르면서 미입고 수량이 양수인 행을 '지연'으로 분류해. 
- 발주 행 수, 미입고 행 수, 지연 행 수, 중요 지연 행 수, 지연 미입고 금액을 계산해. 
- 금액은 지연 행별 미입고 수량에 해당 단위당 단가를 곱한 뒤 합산해.

[형식]
- analysis.py에 load_material, enrich, metrics, supplier_summary 함수를 작성해.
- outputs/에 material_metrics.json, supplier_summary.csv, overdue_orders.csv를 저장해.
- .venv의 Python으로 실행하고 결과와 계산 근거를 알려 줘.

[제한]
- 원본 CSV를 수정하지 마.
- 기준일 당일 납기는 지연에서 제외해.
- KG·M·EA 수량을 합산하지 마.
2차시 검증

02_test — 자재 분석 검증하기

작업 대상: starter/02_material • unittest 기반 test_checks.py 작성 및 경계 조건 검증

[역할]
너는 납기 분석의 경계 조건을 검증하는 Python 개발자야.

[맥락]
02_material에 자재 납기 분석 코드가 있어. 작은 고정 예제로 계산을 확인하려고 해.

[명령]
다음 세 가지를 검증해 줘.
- 기준일 당일 납기가 지연에서 제외되는가
- 100개 중 40개가 입고되면 잔량이 60개인가
- 완납 품목이 미입고·지연에서 제외되는가

[형식]
- Python 내장 unittest로 test_checks.py를 작성해서 실행해. 
- 테스트 결과를 알려 주고, 통과하면 Git에 포함할 파일과 제외할 파일도 설명해 줘.

[제한]
이 단계에서는 Git push를 하지 마.

03_dashboard — 자재 납기 대시보드 만들기

작업 대상: starter/02_material • Streamlit 기반 자재 납기 관제실 app.py 개발 (KPI, 차트, 다운로드)

[역할]
너는 자재 납기 현황을 보여 주는 Streamlit 앱 개발자야.

[맥락]
02_material을 계속 사용해. 기존 analysis.py의 계산을 재사용하고 기준일 기본값은 2026-11-13으로 설정해.

[명령]
- '자재 납기 관제실' 화면을 만들어 줘. 
- 기준일, 호선·공급사 선택, 중요 자재 체크, KPI 4개, 공급사별 지연 미입고 금액 막대그래프, 지연 목록과 CSV 다운로드를 넣어 줘.
- 빈 필터 선택은 데이터 없음으로 표시해.

[형식]
- app.py를 작성하고 requirements.txt에 실제 사용하는 pandas와 streamlit의 검증된 버전을 지정해.
- 실행 명령과 화면에서 확인할 항목을 알려 줘.

[제한]
- 파일 경로는 app.py의 위치를 기준으로 처리해.
- 원본 CSV와 기존 분석 계산을 유지해.
- 빈 필터를 전체 선택으로 처리하지 마.

04_quality — 용접검사 분석과 대시보드 만들기

작업 대상: starter/04_quality • weld_inspections.csv (300행) 분석, 불합격률 계산, quality_app.py 개발

[역할]
너는 용접검사 데이터를 분석하고 Streamlit 화면을 만드는 Python 개발자야.

[맥락]
- starter 아래 04_quality의 data/weld_inspections.csv를 사용해.
- 검사 데이터는 300행이야.

[명령]
- 먼저 컬럼과 행 수를 확인하고 변경 계획을 알려 줘. 
- 검사 수, 불합격 수, 공정별 불합격률을 계산해. 불합격률은 불합격 수 합계 ÷ 검사 수 합계 × 100으로 계산하고, 검사 수 합계가 0이면 '해당 없음'으로 표시해. 
- 불합격 수가 검사 수보다 큰 행은 오류로 알려 줘.

[형식]
- quality_analysis.py에 load_quality, quality_metrics, by_process 함수를 작성해.
- outputs/에 quality_metrics.json과 process_quality.csv를 저장해.
- quality_app.py에는 호선·공정 필터, 검사 수·불합격 수·불합격률, 공정별 불합격률 그래프, 선택 데이터 표와 CSV 다운로드를 넣어 줘.
- .venv의 Python으로 검증해.

[제한]
- 원본 CSV와 다른 차시 폴더를 수정하지 마. 
- 행별 불합격률의 평균을 쓰거나 실제 선박의 품질 합격 기준을 임의로 정하지 마.

[역할]

recover — 작업 중단과 오류 진단

작업 대상: 모든 차시 폴더 공통 • 실습 중 에러 발생 시 상태 확인, 원인 진단 및 최소 수정 계획 수립

[역할]
너는 실습 중 오류를 진단하는 지원 담당자야.

[맥락]
현재 차시의 작업 폴더에서 방금 실행한 작업의 상태를 확인하려고 해.

[명령]
- 방금 작업을 중단해.
- 실제 변경한 파일, 실행한 명령, 실패한 지점을 확인해 줘.
- 오류 원인을 진단하고 고칠 파일과 최소 수정 계획을 제시해.

[형식]
변경 파일, 실행 명령, 실패 지점, 오류 원인, 최소 수정 계획 순서로 알려 줘.

[제한]
- 이번 요청에서는 진단과 계획까지만 진행해.
- 원본 CSV 수정, 파일 삭제, 재설치, Git push를 하지 마.
