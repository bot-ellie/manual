2. 리스트 [ ] TABLE_HEADERS — 보고서 표의 머리글(컬럼 순서) 기준표

코드 22번째 줄

대괄호 [ ... ]로 묶인 데이터 목록을 리스트(List)라고 부릅니다. 변수 이름이 모두 대문자(TABLE_HEADERS)인 이유는 프로그램 실행 중에 바뀌지 않는 '고정 기준표(상수)'라는 뜻입니다.

TABLE_HEADERS = ["발주 ID", "호선", "공급사", "자재", "납기일", "지연일", "미입고 수량", "지연 금액", "중요"]
역할: Markdown 보고서 표(markdown_table)와 HTML 보고서 표(html_table)를 만들 때, 항상 이 9개 열 제목과 이 순서 그대로 표를 그리도록 통일해 주는 설계도 역할을 합니다.

3. if 문 상황에 따라 갈림길을 선택하는 조건문

코드 곳곳에서 활용

if 조건:은 "만약 ~라면 이 코드를 실행하고, 아니면(else) 다른 쪽을 실행해라"라고 지시하는 안전장치이자 분기문입니다. 이 코드에서는 주로 4가지 상황에 쓰입니다.

① 0으로 나누기 에러 방지 (계산 안전장치)
if metrics["inspected_count"] == 0

검사 건수가 0건일 때 나눗셈을 하면 프로그램이 에러로 멈추므로, 0건이면 계산 대신 "해당 없음"을 출력합니다.

② 중요 지연 자재 유무에 따른 경고 문구 분기
if important else "- 중요 지연 없음."

중요(critical == "Y") 지연 건이 1건이라도 있으면 "먼저 확인하세요" 안내 문구를 넣고, 없으면 "중요 지연 없음"을 넣습니다.

③ 실행 로그(run_log.csv) 제목 줄 중복 방지
if needs_header: writer.writeheader()

로그 파일이 처음 만들어질 때만 맨 윗줄 컬럼명을 쓰고, 이미 파일이 있으면 기존 내용 아래에 실행 기록 한 줄만 추가합니다.

④ 프로그램 시작 스위치 (맨 아랫줄)
if __name__ == "__main__": main()

터미널에서 이 파일을 직접 실행했을 때만 main() 함수를 눌러 전체 작업을 시작하라는 파이썬 표준 출발 신호입니다.

4. def 함수 & -> None 작업 단위(함수) 정의하기와 반환값 표시법

코드 25~185번째 줄

def(define의 약자)는 특정 작업을 수행하는 기계(함수)를 조립해 이름을 붙여두는 문법입니다. 재료를 괄호 ( )로 넣고, 작업이 끝나면 결과물을 return으로 돌려줍니다.

Case A. 결과값을 돌려주는 함수 (-> str)
def money(value: float) -> str:
    return f"{int(value):,}원"
  • def money(...) : money라는 이름의 금액 변환 기계를 만듭니다.
  • value: float : 입력 재료로 숫자(소수점 포함 가능)를 받겠다는 안내(타입 힌트)입니다.
  • -> str : 작업이 끝나면 문자열(str) 형태의 결과(예: "4,010,660,000원")를 return으로 돌려준다는 표시입니다.
Case B. def main() -> None: 에 붙은 None의 역할
def main() -> None:
    parser = argparse.ArgumentParser(...)
    ...
    run(args.as_of, args.data_dir, args.output_dir)
  • None의 뜻: 영어 그대로 "돌려주는(return) 결과값이 없다"는 의미입니다.
  • 왜 없을까요? main()이나 run() 함수는 계산된 숫자 하나를 뱉어내는 기계가 아니라, 파일을 폴더에 저장하고 화면에 print()로 진행 상황을 출력한 뒤 임무를 마치는 총괄 지휘자이기 때문입니다.
  • 실행에 영향을 주나요? 아니요! -> None은 사람이 코드를 읽을 때 "이 함수는 리턴값이 없는 실행 전용 함수구나"라고 쉽게 이해하도록 붙이는 메모(타입 힌트)일 뿐, 없어도 똑같이 작동합니다.

파이썬 파일은 위에서부터 def로 함수들을 정의만 해두고, 맨 마지막 줄 main()이 호출되면서 실제 작업이 시작됩니다.

수식 점검 전 반드시 알아야 할 구조적 특징!

daily_brief.py 안에는 ① 직접 수식으로 계산·필터링하는 부분과, ② 외부 파일(analysis.py, quality_analysis.py)에서 이미 계산된 결과를 가져와 화면에 표시만 하는 부분이 나뉘어 있습니다. 집계가 틀어졌다면 어느 파일의 어느 수식을 의심해야 하는지 정확히 구분해 드립니다.

수식 영역 1 · 직접 계산 용접 품질 누적 필터링 & 불합격률(%) 계산 (quality_until 함수, 29~38줄)

이 파일에서 직접 계산함 
def quality_until(path: Path, as_of: str) -> dict:
    quality = load_quality(path)
    # [계산 1] 날짜 비교 필터링: 기준일(as_of) 당일까지의 검사 데이터만 추출
    cumulative = quality[quality["inspection_date"] <= pd.Timestamp(as_of).normalize()]
    metrics = quality_metrics(cumulative)
    # [계산 2] 불합격률 백분율(%) 수식 계산
    metrics["rejection_rate_display"] = (
        "해당 없음"
        if metrics["inspected_count"] == 0
        else f"{metrics['rejected_count'] / metrics['inspected_count'] * 100:.4f}%"
    )
    return metrics
A 기준일 누적 범위 조건식 (<=)

quality["inspection_date"] <= pd.Timestamp(as_of).normalize()

  • 계산 의미: 검사일(inspection_date)이 기준일(as_of)보다 작거나 같은(당일 포함) 모든 과거~당일 데이터를 누적합니다.
  • 점검 포인트: 자재 지연은 "기준일 당일 미포함(<)"이지만, 품질 검사는 "기준일 당일 포함(<=)"입니다. 또한 .normalize()로 시·분·초를 00:00:00으로 맞춰 날짜 단위 비교 오차를 막습니다.
B 전체 불합격률 가중 평균 수식
불합격률(%) = (누적 불합격 건수 ÷ 누적 검사 건수) × 100
  • 계산 의미: 각 행의 불합격률을 단순 평균 내지 않고, 전체 불합격 건수 총합(rejected_count)을 전체 검사 건수 총합(inspected_count)으로 나눈 뒤 100을 곱합니다.
  • 표시 자리수: :.4f% 포맷으로 소수점 넷째 자리까지 반올림하여 문자열로 표시합니다. (예: 1157 / 10793 * 100 → 10.7199%)

수식 영역 3 · 반올림/버림 주의 금액 및 수량 정수 변환 계산 (money · report_rows · aggregation_hash)

소수점 버림(int) 발생 지점
⚠️ int(value) 함수의 계산 방식 (소수점 이하 버림)

money() 함수의 int(value), report_rows()의 int(row.remaining_qty), int(row.delay_days)는 반올림(round)이 아니라 소수점 아래 숫자를 무조건 버리는 정수 변환입니다.

예) remaining_value_krw = 1500.9 → int(1500.9) → "1,500원"
