실습 워크플로우 표준

Git & GitHub 5단계 핵심 워크플로우

1. 초기화 & 식별 init, config
2. 변경 확인 status, diff
3. 스테이징 & 검증 add, diff --cached
4. 커밋 & 로그 commit, log
5. 원격 연동 (gh/push) remote, push, gh

저장소 초기화 및 사용자 정보 등록

새 폴더에서 Git 타임머신 기록을 시작하고, 커밋에 남길 작업자 신원(이름, 이메일)을 설정합니다.

기본 브랜치를 main으로 지정하여 Git 저장소 초기화 (.git 생성) git init -b main
현재 저장소에서 사용할 작업자 이름 설정 (로컬) git config user.name "본인 이름"
GitHub 잔디 연동을 위한 이메일 주소 등록 git config user.email "본인 Git 이메일"

변경 사항 감지 및 코드 차이 비교

파일이 어떻게 변경되었는지 스테이징 전에 확인하는 필수 점검 명령어입니다.

간결한 2글자 기호(??, M 등)로 현재 상태 요약 표시 git status --short
아직 스테이징(add)되지 않은 파일들의 구체적인 줄 단위 변경 내역 비교 git diff

스테이징(Staging), 커밋 전 검증 및 스냅샷 기록

변경 파일을 선별해 무대에 올리고, 사전 검증 후 로컬 타임머신 기록(커밋)을 남깁니다.

프로젝트 환경 및 지침 파일 스테이징 등록 git add .gitignore AGENTS.md requirements.txt
실습 데이터 및 소스코드, 테스트 파일 스테이징 등록 git add data/material_orders.csv analysis.py test_checks.py
스테이징된 파일들의 변경 통계(추가/삭제 줄 수 요약) 확인 git diff --cached --stat
커밋 직전, 스테이징된 실제 코드 변경 내역 최종 상세 검토 git diff --cached
메시지와 함께 로컬 저장소에 영구 커밋(스냅샷) 생성 git commit -m "Add material delay analysis"
가장 최근 커밋 1건을 1줄 요약 형태로 검증 git log --oneline -1

원격 저장소 상태 점검 및 GitHub 푸시

원격지 주소를 점검하고 로컬 커밋 이력을 GitHub 클라우드로 업로드합니다.

연결된 원격 저장소(origin) 이름과 실제 URL 주소 목록 조회 git remote -v
현재 브랜치 위치 및 남은 변경 사항 상세 점검 git status
현재 작업 중인 브랜치 이름만 확인 (예: main) git branch --show-current
원격지(origin) main 브랜치로 첫 푸시 및 자동 추적(-u) 설정 git push -u origin main
터미널 원스톱 자동화

GitHub CLI (`gh`) 연동 및 원격 저장소 즉시 생성

웹 브라우저를 띄우지 않고 터미널에서 계정 인증, 토큰 연동, 새 Repo 생성 및 첫 푸시까지 끝냅니다.

1단계: GitHub 계정 대화형 로그인 및 인증 gh auth login
2단계: 일반 git 명령어 실행 시 gh 인증 자격 증명을 자동 사용하도록 등록 gh auth setup-git
3단계: 현재 폴더를 GitHub 새 저장소로 생성 + origin 등록 + 즉시 푸시 gh repo create kship-material-myname --public --source=. --remote=origin --push
gh repo create 옵션 상세 안내

• kship-material-myname: 생성될 GitHub 저장소 이름 (본인 이니셜로 변경 가능)

• --public: 공개 저장소 (회사 보안 프로젝트의 경우 --private 사용 권장)

• --source=.: 현재 폴더 내용을 바탕으로 생성

• --remote=origin: 생성된 GitHub 주소를 로컬의 원격지(`origin`)로 자동 설정

• --push: 로컬 커밋 내역을 즉시 업로드
